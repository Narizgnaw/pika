# Pika 主题系统整改方案

## 背景与决策

你的目标：做"可自定义公共页面"。上一个 AI 把它实现成了一套**完整的第三方主题分发生态**（市场 + ZIP 安装 + GitHub 更新 + SSRF + SDK 契约），1497 行单体 service + 缺 repo 层。

经讨论确认以下决策：
1. **不隔离 origin**（部署要简单），但**砍掉主题市场**（拒绝"任何人能投毒主题"的公开入口），保留「本地上传 + 管理员自填 URL 安装」——同源 JS 风险仍在但收敛到"你信错某个 URL"，攻击面可控。
2. **拆分 `theme_service.go`** 1497 行单体为同包多文件，解决可维护性。
3. **新增 repo 层** `ThemeConfigurationRepo`，收口 DB 访问，与项目 agent/monitor/api_key 风格统一。
4. **重写设计文档**，与"砍市场后"的实际架构对齐。

审计确认：`InstallFromURL`（从 URL 安装）+ `validSHA256` + `download*` 与市场逻辑完全独立，砍市场后照常可用。

## 阶段二：拆分 `theme_service.go`（同包多文件 + repo 层）

### 2.1 拆分原则（关键约束）
- **保持 `package service` 不变**，文件拆到 `internal/service/` 下（不引入 `internal/theme/` 子包）。原因：测试 `theme_service_test.go` 同包直接访问未导出字段 `themeDir`（L229）、`mu`（L339）、未导出方法 `installArchiveLocked`（L340），换子包会破坏测试。
- **`ThemeService` struct 保持单一**（字段不变，除删除 marketURL），作为共享状态容器。所有方法仍以 `*ThemeService` 为接收者，只是定义分散到不同文件。Go 原生支持同包多文件。
- **公开接口零变更**：10 个被 handler 调用的导出方法、`NewThemeService`、4 个错误值、3 个导出常量、`ThemeInstallResult` 类型——签名一个不改。

### 2.2 新增 repo 层 `internal/repo/theme_configuration_repo.go`
```
type ThemeConfigurationRepo struct{ db *gorm.DB }
func NewThemeConfigurationRepo(db *gorm.DB) *ThemeConfigurationRepo
func (r *ThemeConfigurationRepo) Get(ctx, themeID) (models.ThemeConfiguration, error)   // ErrRecordNotFound 透传
func (r *ThemeConfigurationRepo) Save(ctx, db *gorm.DB, record) error                   // 支持传入 tx，保留事务原子性
func (r *ThemeConfigurationRepo) Delete(ctx, themeID) error
func (r *ThemeConfigurationRepo) Migrate(ctx, db *gorm.DB, manifest) (map[string]any, error) // 支持传入 tx
```
> 关键：`Save`/`Migrate` 必须接收外部 `*gorm.DB`（既可是 `r.db` 也可是事务 `tx`），因为 `installArchiveLocked`（L649）要求"文件 rename + 配置迁移"同事务原子提交。现有 `migrateConfigurationWithDB(ctx, database *gorm.DB, ...)` 签名已为此设计，repo 直接照搬语义。

## 风险与回退

- **风险点**：阶段二拆文件 + repo 收口是改动面最大的一步。测试同包访问 `mu`/`installArchiveLocked`/`themeDir` 的约束决定了**必须保持同包**（不引入子包），这一点已在方案中遵守。
- **回退**：每个阶段独立可提交。若阶段二出问题，可单独 revert 拆分提交回到"单体 service + repo 层未抽"状态，不影响阶段一砍市场的成果。
- **顺序**：阶段一（砍市场）→ 阶段二（拆分+repo）→ 阶段三（文档）→ 阶段四（验证）。建议每阶段单独 commit，便于 review 和回退。
